Generate a human-readable reference document cataloging all agents, their commands, tools, and capabilities.

**Input**: $ARGUMENTS (optional: output path. Defaults to `docs/agent-catalog.md`)

## Steps

1. **Discover agents** — list all directories under `agents/` that contain a `CLAUDE.md`.

2. **For each agent**, read:
   - `agents/<name>/CLAUDE.md` — extract: mission, triggers, tools, workflow summary
   - `agents/<name>/commands/` — list all command files, read first line of each (the description)
   - `agents/<name>/` — list any supporting files (scripts, reference docs, configs)

3. **Produce the catalog** with this format:

   ```markdown
   # Agent Catalog

   *Auto-generated by /scribe/agent-catalog. Last updated: <date>*

   ## Overview

   | Agent | Mission | Consult |
   |-------|---------|---------|
   | sauron | Monitoring & validation | `/sauron/consult` |
   | designer | Architecture review | `/designer/consult` |
   | deployer | Deployment management | `/deployer/consult` |
   | scribe | Documentation | — |
   | merger | PR merge | — |

   ---

   ## sauron

   **Mission**: You ensure projects are observable and correct.
   **Triggers**: monitoring, metrics, health, dashboards, logging, tests
   **Model**: inherit

   ### Commands

   | Command | Description |
   |---------|-------------|
   | `/sauron/consult` | Answer monitoring/observability questions |
   | `/sauron/inventory` | Catalog all metrics, logs, and health checks |
   | `/sauron/diagnose` | Debug issues using the observability catalog |

   ### Tools

   | Tool | Type | Purpose |
   |------|------|---------|
   | klog | repo (PyPI) | Structured logging reference |
   | nokrashi-tools | repo (PyPI) | Code validation |
   | grafana MCP | MCP | Dashboard management |

   ### Supporting Files

   | File | Purpose |
   |------|---------|
   | monitoring.md | Four-layer monitoring architecture reference |
   | logging.md | Structured logging standards |
   | klog/ | Logging reference implementation |

   ---

   ## designer
   ...
   ```

4. **Write the file** — authenticate as scribe, write to the output path.

5. **Print summary** — show the user a brief count: agents, commands, tools.

## Rules

- Read ALL files, don't guess or assume
- Include every agent, even if it has no commands
- Sort agents alphabetically
- For each command, read the actual file to get the description (first non-empty line)
- Mark the document as auto-generated so humans know not to edit it by hand
