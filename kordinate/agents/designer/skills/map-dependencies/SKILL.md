# map-dependencies

Build a dependency graph covering internal modules, external services, infrastructure, and reverse dependencies.

## Arguments

`$ARGUMENTS` — Required: `<project>`. Optional: `[--reverse]` to scan other projects for references, `[--depth N]` to limit internal dependency depth (default: unlimited).

The project directory must exist at `~/<project>/` or `~/repos/<project>/`.

## Steps

1. Parse project name and flags from `$ARGUMENTS`. If project missing, show usage and exit.

2. Locate the project directory. Check `~/<project>/`, then `~/repos/<project>/`. If not found, report and exit.

3. **Discover project modules** — find Python packages via `__init__.py` files, or top-level module directories. Build a module list.

4. **Map internal imports** — for each Python file, extract `import` and `from ... import` statements that reference internal modules. Build a directed graph (module A -> module B means A imports B).
   - Flag **circular dependencies**: A -> B -> ... -> A
   - Flag **hub modules**: modules imported by >50% of other modules

5. **Detect external service calls** — scan for:
   - HTTP clients: `requests`, `httpx`, `aiohttp.ClientSession`, `urllib`
   - gRPC: `grpc.insecure_channel`, `grpc.secure_channel`, stub imports
   - Kafka: `confluent_kafka`, `kafka-python`, producer/consumer instances
   - Databases: `psycopg2`, `asyncpg`, `sqlalchemy`, `duckdb`, `sqlite3`
   - Cloud SDKs: `boto3`, `google.cloud`, `azure`
   - Redis: `redis`, `aioredis`
   Record: service type, target (from connection strings/env vars if visible), files using it.

6. **Scan infrastructure dependencies** — check k8s manifests (`manifests/`, `deploy/`):
   - PVCs (persistent storage)
   - StatefulSets (stateful workloads)
   - ConfigMaps and Secrets referenced
   - Service endpoints and ports
   - Init containers and sidecars

7. **Discover inter-service dependencies** — scan `.env`, `config.yaml`, `settings.py` for:
   - Service URLs (env vars ending in `_URL`, `_HOST`, `_ENDPOINT`)
   - Database connection strings
   - Queue/topic names

8. **(--reverse only) Reverse dependency scan** — scan sibling project directories (`~/`, `~/repos/`) for imports or references to this project:
   - Python imports: `import <project>`, `from <project>`
   - Config references: URLs, service names matching project
   - K8s manifests: service references, network policies

9. **Build ASCII dependency graph** — represent the module dependency structure as an ASCII diagram. Keep it readable (collapse modules with single deps).

10. **Write the report** to `<project-repo>/.claude/agent-memory/designer/dependencies.md`:

    ```markdown
    # <project> — Dependency Map

    > Auto-generated by /designer:map-dependencies. Last run: <date>

    ## Module Graph

    ```
    <ASCII dependency graph>
    ```

    ## Internal Modules

    | Module | Imports | Imported by | Role |
    |--------|---------|-------------|------|
    | ... | ... | ... | hub/leaf/standard |

    ## External Services

    | Type | Target | Used by | Config source |
    |------|--------|---------|---------------|
    | HTTP | ... | ... | env/config/hardcoded |

    ## Infrastructure

    | Resource | Type | Namespace | Notes |
    |----------|------|-----------|-------|
    | ... | PVC/ConfigMap/Secret/... | ... | ... |

    ## Reverse Dependencies

    | Project | Reference type | Files |
    |---------|---------------|-------|
    | ... | import/config/manifest | ... |

    ## Risks

    - Circular dependencies: ...
    - Hub modules: ...
    - Hardcoded service endpoints: ...
    - Missing resilience on external calls: ...
    ```

    Create the directory if it doesn't exist. Delegate the .md write to scribe if the guard-md hook blocks you.

11. **Report** — summarize: module count, external service count, circular deps found, hub modules, and report location.
