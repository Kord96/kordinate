Scan a project for all observability signals — metrics, log statements, and health checks.

**Input**: $ARGUMENTS (required: project directory path. Optional: `--output <path>` for catalog file location)

## Steps

1. **Parse arguments** — extract project directory and optional output path. Default output: `<project>/docs/observability-catalog.yaml`

2. **Discover Prometheus metrics** — scan all Python files for metric definitions:
   ```bash
   grep -rn "Counter\|Gauge\|Histogram\|Summary" <project>/ --include="*.py" | grep -v test | grep -v __pycache__
   ```
   For each metric, extract:
   - `name` — the Prometheus metric name string (first arg)
   - `help` — the description string (second arg)
   - `labels` — label names list (if any)
   - `type` — Counter/Gauge/Histogram/Summary
   - `file` — source file path (relative to project root)
   - `line` — line number

3. **Discover log statements** — scan for structlog and stdlib logging calls:
   ```bash
   grep -rn "log\.\(info\|warning\|error\|debug\|critical\|exception\)\|logger\.\(info\|warning\|error\|debug\|critical\|exception\)" <project>/ --include="*.py" | grep -v test | grep -v __pycache__
   ```
   For each log statement, extract:
   - `event` — the event name (first positional arg or `event=` kwarg)
   - `level` — info/warning/error/debug/critical/exception
   - `dimensions` — keyword arguments (structured fields)
   - `file` — source file path
   - `line` — line number
   - `component` — inferred from directory structure or module name

4. **Discover health checks** — scan for health status patterns:
   ```bash
   grep -rn "_set_status\|pipeline_status\|pipeline_.*_status\|health" <project>/ --include="*.py" | grep -v test | grep -v __pycache__
   ```
   For each health check, extract:
   - `section` — the health section name
   - `check` — the sub-check name
   - `values` — mapping of 0/1/2 to meaning (FAIL/WARNING/OK)
   - `conditions` — what triggers each state (from surrounding code context)

5. **Cross-reference with Grafana dashboards** — if dashboard JSON files exist:
   ```bash
   find <project>/agents/deployer/manifests/master/base/dashboards/ -name "*.json" 2>/dev/null
   ```
   For each dashboard, extract all PromQL expressions and check which metrics from step 2 are referenced. Flag:
   - **Unused metrics** — defined in code but not in any dashboard
   - **Missing metrics** — referenced in dashboards but not defined in code

6. **Write the catalog** — produce a YAML file with this structure:
   ```yaml
   # Auto-generated by sauron/catalog-observability
   # Last updated: <timestamp>
   # Project: <project name>

   metrics:
     - name: pipeline_flush_duration_seconds
       type: Histogram
       help: "Time spent in flush callback"
       labels: [consumer]
       file: lib/metrics.py
       line: 32
       dashboards: [operational-health]

   logs:
     - event: slot_complete
       level: info
       dimensions: [slot_id, files, parsed, published, duration_s]
       component: message-producer
       file: data_source/logServer/messageProducer/pipeline.py
       line: 190

   health_checks:
     - section: ingestion
       check: producer
       ok: "message-producer process running"
       warning: "process running but lagging"
       fail: "process not running"
       file: monitor/sentinel.py
       line: 380

   coverage:
     total_metrics: 28
     metrics_in_dashboards: 25
     unused_metrics: [metric_a, metric_b]
     missing_from_code: []
   ```

7. **Print summary** to the user:
   ```
   ## Observability Catalog: <project>

   | Category | Count |
   |----------|-------|
   | Metrics  | 28    |
   | Log events | 145 |
   | Health checks | 21 |

   Coverage: 25/28 metrics referenced in dashboards
   Unused: metric_a, metric_b, metric_c
   Written to: docs/observability-catalog.yaml
   ```

## Rules

- Do NOT include test files in the scan
- Group log events by component (inferred from directory/module)
- For metrics with labels, list all observed label values if discoverable from code
- If the project has an `agents.yaml`, cross-reference its `key_metrics` with discovered metrics
- Commit with `[sauron] scan: update observability catalog`
