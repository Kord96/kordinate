# Infrastructure Reference

Canonical source of truth: `memory/global/infra-atlas.json` (generated by `/survey`).
This file provides operational context and ownership rules.

## Cluster

Single k3s cluster: **homeserver** (ottawa). Active node: `homeserver` (20 CPU, 64Gi).
Two legacy nodes (`colima`, `kkord-latitude-5420`) are SchedulingDisabled.

## Namespaces

| Namespace | Purpose | Key workloads |
|-----------|---------|---------------|
| `kord` | Agent platform | Agents, scribes, job-router, webhook-receiver, KEDA |
| `master` | Workstation + monitoring backend | Workstation (Caddy), Alloy, Prometheus, Loki, Grafana |
| `dev` | Kafka message bus | Strimzi Kafka (broker + entity operator) |
| `gateway` | Ingress + object storage | MinIO |
| `monitor` | Agent log collection | Alloy (ships agent logs to Loki in master) |
| `registry` | Container images | Registry (NodePort 30500) |
| `prod` | Production workloads | Project apps, Kafka, Postgres, Redis |

## PVC Layout

| PVC | Namespace | Size | Access | Purpose |
|-----|-----------|------|--------|---------|
| `agent-runtime` | kord | 20Gi | RWX | Shared `/kord` mount for all agents, scribes, job-router |
| `kord` | master | 20Gi | RWX | Workstation kord volume |
| `kord-repos` | master | 20Gi | RWX | Workstation repo storage |
| `workstation-home` | master | 20Gi | RWO | Workstation home directory |

## Agent Platform (kord namespace)

All agent workloads run in `kord`, not `master`. Components:

- **Agents** (augur, charon, sauron, warden, alfred) -- Deployments, KEDA-scaled from Kafka topics
- **Scribes** (one per agent) -- Consume `memory.updates.<agent>`, deduplicate with Haiku
- **Job Router** -- HTTP gateway (`job-router.kord.svc.cluster.local:3100`), delegates to agents via Kafka
- **Webhook Receiver** -- GitHub push events, routes to job-router for CI triggers
- **Kafka** in `dev` namespace -- `kafka-kafka-bootstrap.dev.svc.cluster.local:9092` (Strimzi-managed)

All pods use image `localhost:30500/agent-factory:latest` from the cluster registry.
Single PVC `agent-runtime` mounted at `/kord` provides shared memory, repos, and team data.

## Workstation (master namespace)

Caddy runs inside the workstation pod. Charon patches the Caddy ConfigMap to add/remove routes
for services (docs, dashboards, etc.). The workstation also hosts development tools.

### Docs Site

Astro + Starlight at `docs.khaledkord.com`. Deployment in master namespace with git-sync
(pulls Kord96/kordinate-docs every 3s). Has password auth via Vite plugin — cookie-based,
no OAuth. Passwords managed by alfred (`kordinate/docs/dev_password`, `kordinate/docs/guest_password`).

Headless access: `curl -b "dev-auth=ok" http://docs.master.svc.cluster.local:80/...`
or POST to `/dev/login` with `password=<dev_password>&role=admin`.

## Dev Deployment Model

Dev services use **git-sync sidecar** pattern (see `docs.yaml` for reference):
- git-sync container polls the repo every **3s**
- App container mounts the synced volume read-only
- File watchers in the app detect changes for hot reload
- No image rebuild needed for dev iteration

## Build Pipeline

```
GitHub push -> webhook-receiver -> job-router -> charon (via Kafka)
```

Charon runs deterministic gates (lint, test, schema drift) before building.
Builds use **kaniko** Jobs. Images push to `localhost:30500/<name>:latest`.
`--cache-from` the registry image for layer caching. Never delete the latest pushed image.

## Networking

- Internal: ClusterIP services, DNS `<svc>.<ns>.svc.cluster.local`
- External: Cloudflare tunnels for public endpoints
- Mesh: Tailscale between clusters
- Registry: `localhost:30500` (NodePort)

## Manifests

Platform manifests: `agents/charon/skills/platform/manifests/base/`
  - `agents.yaml`, `scribes.yaml`, `job-router.yaml`, `webhook-receiver.yaml`
  - `kafka.yaml`, `keda.yaml`, `docs.yaml`
  - `kustomization.yaml` ties them together

Manifests are namespace-agnostic -- always `kubectl apply -n <namespace>`.

## Credentials

- `pass` store (`kordinate/`) -- GPG-encrypted, managed by Alfred
- k8s Secrets created from `pass` at deploy time (e.g., `anthropic-api`, `github-webhook`)
- Never hardcode credentials in manifests
