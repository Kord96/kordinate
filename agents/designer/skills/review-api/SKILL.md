# review-api

Scan a project's HTTP API surface against api-gateway and hexagonal patterns.

## Arguments

`$ARGUMENTS` — Required: `<project>` (e.g., `logbd`, `stoik`). The project directory must exist at `~/<project>/` or `~/repos/<project>/`.

## Steps

1. Parse project name from `$ARGUMENTS`. If missing, show usage and exit.

2. Locate the project directory. Check `~/<project>/`, then `~/repos/<project>/`. If not found, report and exit.

3. **Detect web framework** — scan for imports and config:
   - Flask: `from flask import`, `Flask(__name__)`
   - FastAPI: `from fastapi import`, `FastAPI()`
   - Django: `urlpatterns`, `django.urls`
   - Starlette: `from starlette`, `Starlette(`
   - aiohttp: `from aiohttp import web`, `web.Application()`

4. **Discover route definitions** — find all route/endpoint declarations:
   - Flask: `@app.route`, `@blueprint.route`
   - FastAPI: `@app.get/post/put/delete/patch`, `@router.get/post/...`
   - Django: `path(`, `re_path(`, `url(`
   - Build table: method, path, handler function, file location

5. **Check route naming consistency** — routes should use kebab-case, plural nouns, no verbs:
   - RECOMMENDED if mixing conventions (e.g., `/get-users` vs `/users`)
   - MINOR if inconsistent casing (camelCase vs kebab-case)

6. **Check API versioning** — look for `/v1/`, `/v2/`, or `api_version` patterns:
   - RECOMMENDED if no versioning strategy detected
   - MINOR if inconsistent versioning across routes

7. **Check error response format** — look for global error handlers, shared error schemas:
   - RECOMMENDED if no global error handler found
   - MINOR if inconsistent error formats across handlers

8. **Check auth middleware coverage** — per-route auth decorators, default-deny patterns:
   - CRITICAL if routes without auth and no default-deny middleware
   - RECOMMENDED if auth is per-route without a default-deny base

9. **Check rate limiting** — look for rate limiter middleware or decorators:
   - RECOMMENDED if no rate limiting detected on public endpoints

10. **Check request/response validation** — Pydantic models, marshmallow schemas:
    - RECOMMENDED if handler parameters lack validation
    - MINOR if validation exists but is inconsistent

11. **Check gateway compliance** — routes should delegate to service/use-case layer, not contain business logic:
    - CRITICAL if route handlers contain direct DB queries, complex logic, or domain operations
    - RECOMMENDED if handlers mix delegation and inline logic

12. **Check hexagonal compliance** — handlers should not import infrastructure directly:
    - CRITICAL if handlers import DB drivers, external clients, or infra modules directly
    - RECOMMENDED if adapters are partially mixed with domain code

13. **Report** — summarize findings to the caller: framework detected, endpoint count, critical findings, and where the full report was written.
